# 地图难度与计时赛道设计

## 背景

当前 FPV-ONLINE 只有一张自由飞行地图：随机分布的 10 根柱子，没有碰撞、计分或目标。玩家希望增加第二套更高难度的地图，包含方框、FPV 穿门等障碍，并在页面上提供难度切换入口。

## 目标

- 保留现有简单地图及自由飞行手感。
- 新增一张带完整玩法的困难地图：顺序穿门、计时、完成提示。
- 困难地图加入柱子、实心方箱、圆形/方形穿门等障碍，并提供碰撞反馈。
- 页面右上角提供地图切换入口，切换后状态完整重置。

## 非目标

- 不做联机、排行榜、成绩持久化。
- 不重构飞行物理模型，不改变简单地图的手感和碰撞行为。
- 不做移动端触屏操控。
- 不引入构建工具或新框架。

## 交互与 UI

### 地图切换

- 右上角固定两个按钮：`简单地图`、`困难地图`，当前地图高亮。
- 切到简单地图：隐藏赛道 HUD 和完成提示，回到自由飞行。
- 切到困难地图：重置飞行器、赛道与计时，显示赛道 HUD。
- 切换时销毁旧地图的几何体、材质与贴图，避免重复切换造成显存泄漏。

### 赛道 HUD

困难地图下在页面顶部居中显示：

- `穿门 0 / 8`
- 未开始：`等待开始 — 推油门或拨动摇杆`
- 计时中：`用时 00:12.34`
- 完成后：`用时 00:23.45`（停止更新）

### 完成提示

- 穿过 8 号门后显示居中浮层：`赛道完成！`、最终用时、`再来一次` 按钮。
- `再来一次`：保留困难地图，飞行器回到起点，赛道与计时归零，隐藏浮层。
- 切换到其他地图也会关闭浮层。

## 地图设计

### 共用环境

简单/困难地图共用现有环境：灰色天空、绿色棋盘格地面、黄色太阳、平行光。环境只创建一次，切换地图时只替换障碍物分组。

### 简单地图（自由飞行）

- 保持现状：10 根随机位置的绿色高柱，无赛道、无计时。
- 起点与原版一致：`(0, 0.1, 0)`，朝向 `-Z`。
- 仅保留原有地面碰撞，不增加柱体碰撞，避免改变现有手感。

### 困难地图（计时赛道）

- 起点：`(0, 2, 20)`，朝向 `-Z`。
- 8 道编号门沿 S 形路线分布，圆形环与方形门交替：

| 序号 | 位置 (x, y, z) | 类型 | 偏航角 |
|---|---|---|---|
| 1 | (0, 3, 10) | 方形 | 0° |
| 2 | (-10, 6, 2) | 圆形 | 25° |
| 3 | (8, 3, -8) | 方形 | -25° |
| 4 | (-6, 8, -16) | 圆形 | 20° |
| 5 | (10, 5, -25) | 方形 | -30° |
| 6 | (-10, 7, -32) | 圆形 | 25° |
| 7 | (4, 4, -38) | 方形 | -15° |
| 8 | (0, 6, -44) | 圆形 | 0° |

- 方形门洞 6×6 米，边框厚 0.5 米；圆形门半径 3 米，管径 0.3 米。
- 每道门上方悬浮编号牌（用 CanvasTexture 生成的 Sprite），方便按顺序寻找。
- 下一道目标门高亮绿色；已通过的门变暗。
- 障碍物：
  - 12 根细高柱（截面约 1×1 米，高 8–14 米），布置在门与门之间形成绕行路线。
  - 5 个实心方箱（边长 4–6 米，部分悬空或落地），挡住直线路径。

## 赛道规则

### 计时

- 切到困难地图后不立即计时。
- 首次有效操控时开始计时：按下任一飞行键，或手柄任一轴相对地图加载时的值变化超过 0.1。
- 计时使用 `performance.now()`，显示格式 `mm:ss.cs`。
- 穿过 8 号门后停止计时并显示完成浮层。

### 穿门判定

- 必须按 1→8 顺序穿过；未轮到或已通过的门不计入进度。
- 判定方式：记录飞行器上一帧与当前帧相对门平面的带符号距离，符号发生变化时，用线性插值求出穿越点。
- 穿越点必须落在门洞范围内（横向和纵向均在半宽/半高内）才算通过。
- 通过后进度加一，当前门变暗，下一道门高亮。

### 碰撞

- 仅困难地图启用柱体、方箱和门框碰撞；简单地图保持仅地面碰撞。
- 飞行器视为半径 0.5 米的球体：
  - 柱体、方箱用 AABB 与球体求交。
  - 方形门框、圆形门环在门的局部坐标系中判定，避免整体包围盒堵死门洞。
- 碰撞响应：沿最小穿透方向把飞行器推出，法向速度反向并乘以 0.35，切向速度乘以 0.7，计时继续。

## 代码结构

### 新增 `src/maps.js`

导出：

- `buildEasyMap()`：返回 `{ group, spawn, obstacles, gates }`。
- `buildHardMap()`：返回同样结构，包含 8 道门与障碍物。
- `disposeGroup(group)`：递归释放几何体、材质与贴图。

数据结构：

- `spawn`: `{ position: Vector3, rotation: Euler }`
- `obstacles`: `{ min: Vector3, max: Vector3 }[]`
- `gates`: `{ center, normal, lateral, halfWidth, halfHeight, mesh, number }[]`

### 新增 `src/race.js`

`Race` 类负责：

- `load(gates)`：绑定当前地图的门与 HUD。
- `noteInput()`：首次操控时启动计时。
- `update(position)`：顺序穿门检测、HUD 刷新、完成判定。
- `reset()`：清空进度与计时。
- `showResult()/hideResult()`：控制完成浮层。

### 修改 `src/engine.js`

- 环境（地面、太阳、灯光）只创建一次。
- 用 `loadMap(name)` 替换障碍分组、设置出生点、重置飞行状态和赛道。
- 增加困难地图碰撞处理；每帧把飞行器位置传给 `Race.update()`。
- 绑定地图切换按钮和「再来一次」按钮。
- 检测首次操控并调用 `Race.noteInput()`。

### 修改 `index.html` / `assets/css/index.css`

- 新增加地图切换器、赛道 HUD、完成浮层节点。
- 样式沿用现有半透明黑底、等宽字体、绿色高亮风格；按钮可点击，其余浮层不拦截画布事件。
- 页面语言标记改为 `zh-CN`。

## 测试与验收

### 自动验证（Playwright + Chrome）

1. 打开页面，默认选中简单地图，赛道 HUD 与完成浮层不可见。
2. 点击「困难地图」：赛道 HUD 显示 `穿门 0 / 8` 和等待开始文案，无控制台报错。
3. 按住 `W` 首次操控后，计时文案从“等待开始”变为运行中的时间。
4. 沿起点正前方飞行穿过 1 号门后，进度变为 `穿门 1 / 8`。
5. 切回简单地图再切回困难地图，进度和计时重置。
6. 两套地图分别截图，人工检查门、编号牌、柱阵、方箱布局与高亮状态。

### 手动验收

- 检查碰撞弹开效果、穿门高亮切换、完成浮层与「再来一次」。
- 检查键盘操控与手柄操控都能触发计时和穿门计数。

## 风险与处理

- 门框碰撞包围盒若处理不当会堵住门洞：圆形/方形门均在门局部坐标中判定。
- 高速飞行可能跨帧穿过门：用前后帧距离符号变化加线性插值判定。
- 频繁切换地图可能泄漏资源：切换时统一调用 `disposeGroup`。
